# Particle opening

The public site is plain HTML served by Python, not a React application. A small React/TypeScript island mounts the opening title and link composer without changing the signed-in dashboard. Their sources are `components/ui/particle-title.tsx` and `components/ui/prompt-composer.tsx`. The landing footer is an Anhy-adapted version of `sakshamfit/orion-gkp`'s Doodle Crew Footer (`components/ui/doodle-crew-footer.tsx` and `orion-footer.css`), with local branding and working Anhy links rather than Orion's logo and destinations. The page's base styles are inline in `landing.html`, its light/dark theme is in `landing-theme.css`, and its Tailwind utilities are generated in `particle-title.css`. Because `web/` is the frontend root, its default component path is `web/components/ui`, not repository-root `/components/ui`; keeping this folder makes the shadcn alias and future UI components consistent. The composer uses `lucide-react` icons and a small `lib/utils.ts` class joiner. No provider or image assets are needed.

After changing either component, from `web/` run `npm ci && npm run build`. Commit the generated `particle-title.js` and `particle-title.css` files because the Python server does not build JavaScript on deployment. `particle/demo.tsx` supplies the title text; edit it to change the copy. `particle/composer-demo.tsx` demonstrates the full model picker API, but the landing page does **not** offer a model picker: models are configured in the app, and implying one here would be misleading. On the landing page, submitting a supported video link and optional special instructions preserves both for signup/app; the signed-in composer also has an instructions field directly below its link. These per-batch preferences are validated (500 characters), saved with the job and passed to the clip-finding AI as untrusted guidance, without overriding its safety rules. The paperclip takes visitors to the workspace for uploads. The light/dark button remembers a choice locally, otherwise follows the OS. The canvas scales to its container and pauses off-screen; reduced-motion visitors see ordinary text. The opening keeps a functional link form without JavaScript. For each finished clip, the AI drafts a grounded social caption and 3–5 relevant hashtags; the editor shows both before posting and lets people change them. Without AI, honest fallback copy/tags are used. No caption or hashtag can guarantee virality, and on-video subtitles stay faithful to what was said.

## Automatic clip editing

When the AI finds a clear spoken punchline or reaction, it may mark up to two beats per clip. The renderer validates each beat against transcript timing, then makes a brief 11% punch-in with a small color lift and an optional low-volume, generated whoosh; captions and the hook are overlaid afterward so they remain legible. If the AI gives no usable timing, spoken highlight words can supply beats; without a matching word the video stays steady. The original audio is retained and normalized. This also works for live clips and with captions off. The pre-clipping look chooser and each clip's re-make editor can turn emphasis or sound off independently. These choices can improve the feel of a clip, not guarantee reach or engagement. A real ffmpeg installation is still required by the application (including ffprobe).

This is not a full shadcn app: only the isolated title uses React. If converting the whole frontend later, initialize a separate TypeScript React project with `npm create vite@latest frontend -- --template react-ts`, then from that project run `npx shadcn@latest init` and install Tailwind following the CLI's Vite prompts. Point the `@/components` alias at that project's source directory, create `components/ui` there, and move the title into it. Do not run the initializer over the existing Python-served HTML pages.
